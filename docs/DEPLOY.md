# Deploying LoanLoop: Vercel (web) + Render (gateway, voice, Postgres, Key Value)

The deployed LLM is Sarvam only (`sarvam-105b-conversations`, hosted). No Ollama service is deployed.

Everything is synthetic data. People sign in with a per-user login (staff at `/staff/login`, customers at `/login`). `WEB_BASIC_AUTH` is an optional extra gate in front of both.

## 1. Generate secrets (once, keep them in a password manager)

```
python -c "import secrets;print(secrets.token_urlsafe(32))"   # run 5 times: GATEWAY_SHARED_SECRET, DASHBOARD_TOKEN, PHONE_TOKEN, VOICE_EDGE_TOKEN, and spare
python -c "from cryptography.fernet import Fernet;print(Fernet.generate_key().decode())"   # ENCRYPTION_KEY (needs `pip install cryptography`, or run via `cd gateway && uv run python -c ...`)
```

Never reuse the three gateway tokens for each other. Losing `ENCRYPTION_KEY` makes stored account/loan numbers unreadable (reseed fixes it on a demo DB).

## 2. Render (gateway, voice, Postgres, Key Value), free plan

`render.yaml` at the repo root is a Render Blueprint for four free resources in Singapore: `loanloop-gateway` and `loanloop-voice` (Docker web services built from `deploy/gateway.Dockerfile` and `deploy/voice.Dockerfile`), `loanloop-redis` (Key Value) and `loanloop-db` (Postgres).

Free-plan limits to plan around:
- Web services sleep after 15 minutes without traffic; the first request then takes about a minute. Before a demo, open both `/health` URLs and wait for `{"ok":true}`.
- 0.1 CPU and 512 MB per service, so gateway actions are slower than on a laptop. Voice turns mostly wait on Sarvam and Gnani.
- Free services cannot receive private-network traffic, so voice and Vercel call the gateway by its public URL.
- No pre-deploy command and no shell on free services: seed from your laptop (section 4).
- Free Postgres expires 30 days after creation; Key Value is in memory only (sessions and live events are lost on restart; bank data is in Postgres).
- The jobs loop only runs while the gateway is awake; the staff console's "run jobs" button still works.

Steps:
1. Render dashboard, **New > Blueprint**, connect this GitHub repo, branch `main`. Render reads `render.yaml`.
2. Fill in the values it asks for (`sync: false`). The service URLs are `https://loanloop-gateway.onrender.com` and `https://loanloop-voice.onrender.com` unless the name is taken (Render then adds a suffix; use what the dashboard shows).

**gateway** (`loanloop-gateway`)

| Var | Value |
|---|---|
| DATABASE_URL, REDIS_URL | set by the Blueprint (`loanloop-db`, `loanloop-redis`) |
| GATEWAY_SHARED_SECRET, DASHBOARD_TOKEN, PHONE_TOKEN | generated by the Blueprint |
| ENCRYPTION_KEY | the Fernet key from section 1. The laptop seed must use the same value. |
| PUBLIC_GATEWAY_URL | `https://<gateway>.onrender.com`. Turns on the guard that refuses dev-default secrets. |
| GNANI_SPEECH_API_KEY | Gnani key |
| DEMO_STAFF_PASSWORD, DEMO_CUSTOMER_PASSCODE | **you must set them.** Your own strong password (12+ characters) and a 6-digit passcode. There are no defaults. Keep them out of Git. |
| SESSION_TTL_S, JOBS_INTERVAL_S | optional (1800, 3600) |

**voice** (`loanloop-voice`)

| Var | Value |
|---|---|
| GATEWAY_URL | `https://<gateway>.onrender.com` (public URL) |
| GATEWAY_SHARED_SECRET, DASHBOARD_TOKEN | copied from the gateway by the Blueprint |
| LLM_PROVIDER | `sarvam` (set by the Blueprint; **required**: the code default is `ollama`, which is not deployed) |
| LLM_FALLBACK | leave unset (no fallback provider is deployed) |
| SARVAM_API_KEY | Sarvam key (`SARVAM_MODEL` is set to `sarvam-105b-conversations`) |
| GNANI_SPEECH_API_KEY | Gnani key |
| WARMUP | `false` (set by the Blueprint) |
| VOICE_ALLOWED_HOSTS | `<voice>.onrender.com` (no scheme). Turns on the public-deploy guard. |
| VOICE_EDGE_TOKEN | generated by the Blueprint; copy it to Vercel |

The images start via `deploy/serve.py` on Render's `$PORT`. Never set `VOICE_DEV`. Leave `VOICE_ALLOWED_ORIGINS` empty (the browser only talks to Vercel).

Order: create the Blueprint, seed (section 4), then set up Vercel.

`deploy/railway/` still holds the Railway config (paid plan) if you move there later.

## 3. Vercel

Import the repo, **Root Directory: `web`**. Env vars (Production):

| Var | Value |
|---|---|
| GATEWAY_URL | `https://<gateway>.onrender.com` |
| WEB_BASIC_AUTH | optional: `user:password` for an extra outer gate. Leave it out to rely on the sign-in pages. |
| WEB_ALLOWED_ORIGINS | `https://<vercel domain>` |
| VOICE_URL | `https://<voice>.onrender.com` |
| VOICE_EDGE_TOKEN | same as voice (Render dashboard, `loanloop-voice`, Environment) |

The web app no longer needs `DASHBOARD_TOKEN` or `PHONE_TOKEN`; do not set them on Vercel. `WEB_AUTH_DISABLED` does nothing any more. Leave `NEXT_PUBLIC_VOICE_URL` unset. `WEB_ALLOWED_ORIGINS` must be the exact production origin, so test POST flows (calls) on the production domain, not preview URLs. The voice proxy route allows up to 300 s per request. Redeploy after changing env vars.

### Staff and customer sites

On a real deployment, serve the staff door and the customer door from separate web addresses (two Vercel projects or two domains built from the same `web` code). Then a staff cookie and a customer cookie never go to the same site. Cookies are marked `Secure` in production, so every address must use HTTPS or sign-in will not stick. Put each address in `WEB_ALLOWED_ORIGINS`.

## 4. Seeding (from your laptop, once)

Free Render services have no pre-deploy step and no shell, so seed the empty database from `gateway/`. In the Render dashboard, open `loanloop-db` and copy its **External Database URL**. Then, in PowerShell:

```
cd gateway
$env:DATABASE_URL = "<External Database URL>"
$env:ENCRYPTION_KEY = "<same key as the gateway on Render>"
$env:DEMO_STAFF_PASSWORD = "<same as on Render>"; $env:DEMO_CUSTOMER_PASSCODE = "<same as on Render>"
$env:REDIS_URL = "redis://localhost:56379/14"   # seed clears ll:* keys; db 14 keeps your local demo's Redis (db 0) untouched
uv run python -m app.db.seed_if_empty
```

Close that PowerShell window afterwards so the env vars don't leak into a local `start.ps1` run.

It seeds only when `customers` is missing or empty and never drops a populated DB. If Render refuses the external connection, set the gateway's **Settings > Docker Command** once to `sh -c "python -m app.db.seed_if_empty && python /app/deploy/serve.py app.main:app 8000"`, deploy, then clear the field.

To reset demo data deliberately (this DROPS all tables), run `uv run python ../tools/seed_data.py` with the same env vars.

## 5. Smoke test

- [ ] `https://<gateway>.onrender.com/health` returns `{"ok":true}` (wait up to a minute if it was asleep); the laptop seed printed `seed_if_empty: database empty, seeded customers: ...`.
- [ ] `https://<voice>/health` returns ok through the Vercel proxy path. Direct: `POST https://<voice-domain>/calls` without the edge token must return 401, and `/health` returns only `{"ok":true}`.
- [ ] `/staff/login` signs in `manager@loanloop.demo` with your `DEMO_STAFF_PASSWORD`; a wrong password is refused (5 wrong tries lock the account for 15 minutes). If `WEB_BASIC_AUTH` is set, the site asks for it first.
- [ ] `/bank` loads with customer data; a customer session cannot open it.
- [ ] `/login` signs in a demo customer (registered mobile and `DEMO_CUSTOMER_PASSCODE`) and opens `/phone` and `/call`.
- [ ] A typed call on the call page completes a verify and an EMI query.
- [ ] `/ops` live events update while the call runs (SSE).
- [ ] Mic works on the call page (HTTPS is required; allow the browser permission).
- [ ] Voice logs show `sarvam` as provider, and a typed turn replies in about a second.

## 6. Rollback

- Render: service, Events, pick the previous successful deploy, Rollback. `render.yaml` lives in git, so reverting the commit also works.
- Vercel: Deployments, previous production deployment, Promote to Production.
- Data: `seed_if_empty` never overwrites data. To restore demo data, run the deliberate reseed in section 4.
- Emergency: suspend `loanloop-voice` or `loanloop-gateway` (service Settings, Suspend) to take it offline.
